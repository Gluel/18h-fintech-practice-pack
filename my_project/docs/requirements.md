# 요구사항 명세 (명세 4칸 × 3)

> 이 파일은 **여러분이 고쳐 쓰는 파일**입니다. 회색 예시 줄은 지우고 내 문장으로 바꾸세요.
> 조사하지 않은 것은 지어내지 말고 「가설」이라고 적습니다.

「잘 되게 해 줘」는 확인할 수 없습니다. **상태 · 조건 · 결과 · 실패** 네 칸으로 바꿉니다.

| 요구 | 상태 — 지금 화면이 어떤 상태인가 | 조건 — 무엇이 들어오면 | 결과 — 무엇이 보여야 하나 | 실패 — 안 될 때 무엇을 보여주나 |
| --- | --- | --- | --- | --- |
| **R-01 · 정상** |  |  |  |  |
| **R-02 · 빈 값** |  |  |  | (「미공개」 — 0 이 아닙니다) |
| **R-03 · 오류** |  |  |  | (그 줄만 「확인 필요」 — 화면 전체를 멈추지 않습니다) |

세 개면 충분합니다. **정상 1 · 빈 값 1 · 오류 1.** 이 세 줄이 기본 검사입니다. 계산 기능을 선택했다면 R-04(입력·계산식·결측 처리·기대값)를 추가하고 검사 분모도 4로 맞춥니다. 공통 참고본은 상태 3개+계산 1개로 4/4입니다.

## AI 에게 구현을 맡길 때 그대로 붙여넣을 문장

```
my_project/docs/requirements.md 의 R-01 «하나만» 구현해줘.
고쳐도 되는 파일은 my_project/index.html 하나야. my_project/data/ 는 읽기만 해.
끝나면 바꾼 파일 목록과 내가 화면에서 확인할 방법을 알려줘.
```

한 번에 세 개를 다 시키지 않습니다. 하나씩 해야 무엇 때문에 달라졌는지 알 수 있습니다.
