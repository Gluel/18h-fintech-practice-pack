# 뉴스 옆 관련 지표 · A1~A6 완성 예시
교육용 가설·교사 참고 예시입니다. 고객 인터뷰·학생 수행 결과가 아닙니다.
3일 내내 쓰는 공통 사례이며, 개인 주제로 바꿀 때도 칸의 구조는 그대로입니다.

## A1 기획
|핵심 칸|가설|
|---|---|
|고객군|첫 주식 투자를 시작한 1~2년차 직장인. 사용자와 지불자가 같다는 가설|
|문제|뉴스를 봐도 어느 지표를 봐야 할지 몰라 판단을 미룬다|
|가치|뉴스 한 건 옆에서 관련 지표의 값·시점·출처를 같이 확인한다|
|솔루션|뉴스 5건 목록 → 한 건 선택 → 발행월 지표 값·연월·출처 표시|
|수익|없음(수업 데모). 실제라면 구독 여부를 검증해야 함|
|비용|데이터 갱신 확인·원문 확인 인건비·배포 비용 가설. 아직 산정하지 않음|
채널 가설은 증권 앱 뉴스 탭이며 수업 제출 경로(패들렛)와는 구분합니다. 지표는 「지표까지 보고 판단을 기록한 뉴스 건수」, 검증된 경쟁 우위는 없고 출처·수집일·한계를 화면에 적는 것이 차별점 가설입니다.
여정: 뉴스를 읽는다(숫자가 뉴스에 없다) → 관련 지표를 찾는다(기간·단위가 제각각) → 판단을 미룬다(출처 확인이 어렵다). 생각·불편은 가설입니다.
사용자 이야기: 첫 투자자는 뉴스의 근거를 확인하기 위해 관련 지표의 값과 그 시점을 같은 화면에서 보고 싶다.

## A2 요구와 기대값
- 입력: `data/news_sample.js`(뉴스 5건 — 제목·주소·발행일·출처) + `data/kr_ltir.js`(한국 장기금리 월간 · OECD · 2026-08 = 4.29%).
- R-01 정상: 뉴스 5건의 발행월 지표가 모두 있을 때 → 5행 모두 값·연월·출처. AC-01: 위 두 파일이 주어지면 표 5행에 제목(원문 링크)·발행일·지표 값·연월·출처가 보인다.
- R-02 빈 값: 그 달 관측이 없으면 그 행만 「미공개」. 나머지 4행은 그대로. **0%로 채우지 않습니다.**
- R-03 오류: 지표 값이 숫자가 아니면 그 행만 「확인 필요」. 나머지 행과 화면은 유지.
- R-04 계산: 20일 이동평균은 20개가 모였을 때만 계산. 그 전에는 「20일이 모이면 표시」. 화면의 평균과 차트가 같은 규칙을 씁니다.
- 와이어프레임: 위에 뉴스 목록, 가운데 선택한 뉴스의 지표 카드(값·연월·출처), 아래 상태·한계. 예외 문구에는 다음 행동을 포함.
- 제외: 실시간 시세·계좌연결·로그인·외부전송·매매추천.

## A3 작은 작업
T-01 입력검사 → `parseRates` / R-03 / IT-04.
T-02 뉴스↔지표 결합 → `rateFor`·`joinNews` / R-01·R-02 / UT-01·IT-01.
T-03 상태표시 → `draw` / R-01·02·03 / E2E-01~03.
T-04 이동평균 → `movingAverage` / R-04 / UT-04·UT-05.
위 함수는 `browser_lab.html`(브라우저)과 `news_rates_reference.py`(Python)의 교사 참고 코드이며 **같은 요구 ID** 를 씁니다. 자기 프로젝트에서는 자기 파일·함수로 바꿉니다.

## A4 검사 계획 · 결과를 미리 채우지 않습니다
|ID|입력·행동|기대|학습자가 실행한 실제 결과|
|---|---|---|---|
|UT-01|지표 조회 2026-08|4.29%|NOT_RUN|
|UT-02|없는 달 조회|미공개 · 값 null|NOT_RUN|
|UT-04|2일치로 20일 평균|계산하지 않음(null)|NOT_RUN|
|IT-01|뉴스 5건 + 정상 지표|5행 모두 값·연월|NOT_RUN|
|IT-02|한 달 빠진 지표|그 행만 미공개 · 4행 유지|NOT_RUN|
|E2E-01|화면에서 뉴스 선택|값·연월·출처가 보임|NOT_RUN|
|E2E-02|미공개 달 선택|이전 값이 사라짐|NOT_RUN|
|E2E-03|값에 글자 → 정상 복귀|확인 필요 → 5행 회복|NOT_RUN|
Q1~Q8에는 해당 검사 ID를 연결하고 실제는 이 표에 한 번만 기록합니다.

## A5 결함과 개선 시연
실습실에서 정상 → 미공개 결함 재현 켜기 → 「한 달 빠짐」을 누릅니다. BUG-01의 의도된 증상은 미공개 행에 앞의 값이 남는 것입니다. UT/IT가 통과해도 화면 E2E는 실패할 수 있습니다.
결함을 끄고 같은 조건을 재검사한 뒤 R-01·R-02·R-03도 다시 확인합니다(회귀). 이는 교사 비교 시연입니다. 본인 앱에 없는 결함을 본인 결함처럼 적지 않습니다.
결함을 못 찾았다면 만들어 내지 않습니다 — 「수정 없음」과 확인한 범위를 적습니다.

## A6 연결과 공유
A1 뉴스 옆 지표 → A2 R-01/AC-01 → A3 T-02 → A4 UT/IT/E2E → A5 실제 개선 또는 수정 없음 → 한계.
45초: 문제 15초 · 실제 동작 20초 · 검사/한계 10초. 실행하지 않았다면 시연 비교라고 말합니다.

기본 목표는 단위1·통합1·E2E 정상/빈/오류입니다. 자동화 환경이 막히면 강사 참고 비교와 직접 화면 검사를 하고, 실행 못한 단위/통합 항목은 NOT_RUN으로 남깁니다. 참고 코드를 돌린 것은 본인 앱의 검사 PASS가 아닙니다.
예시는 교육용 가설이며 실제 고객·사업 성과가 아닙니다. 공통 사례의 기대값은 배포된 kr_ltir.js 의 실제 관측값(2026-08 = 4.29%)에서 가져옵니다.

## 이번에 사용할 양식과 검사 경로
- A1~A6에는 단계별로 한 번만 기록합니다. A1에서 정한 것은 A2가 참조하고, A4의 실제 검사 결과는 QA8 표에 검사ID로 연결합니다.
- `framework_reference/browser_lab.html`: 브라우저만으로 여는 교사 참고 실습. 포털의 검사 실습실과 M5-14 안에도 같은 화면이 있습니다.
- UT/IT는 참고 화면이 쓰는 JavaScript 함수의 검사입니다. E2E는 실제 파일 선택·분류 변경·결과·오류 복구를 확인합니다. 본인 구현의 PASS는 본인 파일에서 실행한 증거로만 기록합니다.
- 빈 결과에는 이전 숫자를 지웁니다. 0원1건은 유효한 결과입니다. 오류 후 정상으로 돌아오는 것까지 확인합니다.
- A5에서 결함이 발견되지 않으면 억지로 만들지 않습니다. 수정 없음·확인 범위를 적고 아직 안 본 조건을 점검합니다.
- 실습실 CSV는 따옴표 없는4열의 제한된 교육 형식입니다. 임의의 금융거래 CSV 전체를 처리하는 도구가 아닙니다.
