린캔버스 나머지3칸, 복수 페르소나, 추가 성능/접근성, 테스트 자동화 확대는 선택입니다.
기본 목표는 단위1·통합1·E2E 정상/빈/오류입니다. 자동화 환경이 막히면 강사 참고 비교와 직접 화면 검사를 하고, 실행 못한 단위/통합 항목은 NOT_RUN으로 남깁니다. 참고 코드를 돌린 것은 본인 앱의 검사 PASS가 아닙니다.
예시는 교육용 가설이며 실제 고객·사업 성과가 아닙니다. 공통 사례의 기대값은 배포된 kr_ltir.js 의 실제 관측값(2026-08 = 4.29%)에서 가져옵니다.

## 이번에 사용할 양식과 검사 경로
- A1~A6에는 단계별로 한 번만 기록합니다. A1에서 정한 것은 A2가 참조하고, A4의 실제 검사 결과는 QA8 표에 검사ID로 연결합니다.
- `framework_reference/browser_lab.html`: 브라우저만으로 여는 교사 참고 실습. 포털의 검사 실습실과 M5-14 안에도 같은 화면이 있습니다.
- UT/IT는 참고 화면이 쓰는 JavaScript 함수의 검사입니다. E2E는 실제 파일 선택·분류 변경·결과·오류 복구를 확인합니다. 본인 구현의 PASS는 본인 파일에서 실행한 증거로만 기록합니다.
- 빈 결과에는 이전 숫자를 지웁니다. 0원1건은 유효한 결과입니다. 오류 후 정상으로 돌아오는 것까지 확인합니다.
- A5에서 결함이 발견되지 않으면 억지로 만들지 않습니다. 수정 없음·확인 범위를 적고 아직 안 본 조건을 점검합니다.
- 실습실 CSV는 따옴표 없는4열의 제한된 교육 형식입니다. 임의의 금융거래 CSV 전체를 처리하는 도구가 아닙니다.
