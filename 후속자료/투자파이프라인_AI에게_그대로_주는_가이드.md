## 0. 먼저 · 이 자료가 아닌 것

이 자료는 **무엇을 사라고 알려주는 자료가 아닙니다.** 종목 추천·목표가·수익 보장·계좌 연결·
자동매매는 없습니다. 여기 있는 것은 **「데이터가 들어와 연구 기록으로 남기까지의 구조」** 하나입니다.

수업에서 만든 것이 「뉴스 옆에 지표 한 줄」이었다면, 이건 그 구조를 끝까지 밀었을 때
어떤 모양이 되는가입니다. 실제 매매에 그대로 쓰지 마세요.

## 1. 전체 모양 — 여섯 단계, 그리고 되돌아오는 세 개의 선

```
1 수집 ──▶ 2 탐지·원인 ──▶ 3 구조화 ──▶ 4 가중·제약 ──▶ 5 검증 ──▶ 6 기록·사람 검토
              ▲              ▲                            ▲            │
              │              │                            └─ 보류면 다시 검증 (6→5)
              │              └───────────────── 임계값 조정안을 만든다 (6→4)
              └──────────────────────────────── 사례로 쌓아 둔다     (6→2)
```

**이 시스템의 성격을 정하는 것은 앞으로 가는 화살표가 아니라 되돌아오는 세 개입니다.**
한 번 지나가고 끝나는 직선이 아니라, 사람 검토에서 다시 앞으로 돌아옵니다.

## 2. 3일 동안 배운 것과 1:1로 대응합니다

| 이 파이프라인 | 3일 과정에서 한 것 |
| --- | --- |
| 원천을 한 파일에 등록하고 등급을 매긴다 | M2 출처 카드 (근거 ID · 확보 범위 · 한계) |
| 못 받아 온 값을 그대로 적는다 | M3 「빈 값은 0 이 아니다」 |
| 무엇을 검증할지 먼저 적는다 | M5 요구사항 명세 4칸 |
| 계산 규칙을 코드 한 곳에 둔다 | M4 이동평균 검산 |
| 통과했다고 끝이 아니다 | M6 회귀 확인 |

## 3. 단계별로 «무엇을 정해야 하는가»

### 1단계 · 수집 — 원천을 한 파일에 모은다

원천 목록이 코드 여기저기에 흩어져 있으면 **무엇을 쓰는지 아무도 말할 수 없게 됩니다.**
그래서 한 곳에 모읍니다.

- 원천마다 적을 것: 이름 · 성격(공식/보도/리서치/커뮤니티) · 연결 상태 · 인용 범위
- **등록했다고 다 들어오는 것이 아닙니다.** 「연결됨 / 구현했으나 미검증 / 계획 / 외부 차단 / 미연동」을
  같은 화면에 적습니다.
- 키가 없어 못 받는 원천은 **「없는 것」으로 처리하고 다른 값으로 메우지 않습니다.**

> **핵심**: 「몇 개를 쓰나」보다 **「어느 것이 아직 연결되지 않았나」**를 같은 화면에 적는 것.

### 2단계 · 등급 — 모든 정보가 같은 자격을 갖지는 않습니다

등급은 「얼마나 믿을 만한가」가 아니라 **「점수에 넣어도 되는가」를 정하는 스위치**입니다.

| 차선 | 무엇이 들어가나 | 점수에 닿나 |
| --- | --- | --- |
| 점수에 반영 | 가격 · 공시 같은 관측된 사실, 보도된 사실 | 반영 (단, 상한이 있음) |
| 맥락으로만 | 애널리스트·기관 리서치, 칼럼 | **0** — 올리지도 내리지도 않음 |
| 무엇을 볼지 고를 때만 | 커뮤니티 · 검색 관심 | **0** — 판단에 안 들어감 |

### 3단계 · 결측 — 못 받았을 때 무엇을 적는가가 절반입니다

| 구분 | 어떻게 적나 | 하지 않는 것 |
| --- | --- | --- |
| 관측값 | 「0」은 값이 없다는 뜻이 아니라 **재어 보니 0** 이라는 뜻. 단위·시점을 같이 | 「없음」과 같은 칸에 넣지 않는다 |
| 미보유·미지원 | 원천 없음 / 값 비었음 / 낡음 을 **각각 그대로** | 0·중립값·동일가중으로 채우지 않는다 |
| 대리값 | 어떤 원본에서 어떤 방법으로 만들었는지, 왜 원래 값을 못 썼는지 | 원래 지표의 이름으로 표기하지 않는다 |

> **결측을 감추면 성과가 좋아집니다.** 그래서 결측을 적는 규칙을 성과 지표보다 **먼저** 정합니다.

### 4단계 · 가중치 — 사실 세 개의 다른 질문입니다

| 층 | 묻는 것 | 바꾸려면 |
| --- | --- | --- |
| 1겹 · 출처 가중 | 이 정보를 점수에 넣어도 되는가 | 정책 변경 (사람 결정) |
| 2겹 · 지표 가중 | 여러 지표를 한 점수로 합칠 때 무엇을 더 볼 것인가 | 코드 변경 + 재검증 |
| 3겹 · 비중 가중 | 각 대상을 얼마로 둘 것인가 | 명세에 적는다 |

층을 나눠 두면 **「성과가 안 나와서 바꿨다」와 「근거가 달라져서 바꿨다」가 구분됩니다.**

> **가중치 설계에서 가장 중요한 값은 흔히 큰 값이 아니라, 0 으로 고정해 둔 자리입니다.**

### 5단계 · 합산 — 못 받아 온 지표는 0점이 아니라 계산에서 빠집니다

```
못 받은 지표를 0점으로 채우면 → 분모는 그대로, 분자만 줄어든다
                              → 데이터가 없을수록 「안전하다」는 결론이 나온다   ✗

분모에서도 빼면              → Σ(점수 × 가중) ÷ Σ(실제로 쓴 가중)
                              → 받아 온 지표만으로 공정하게 평균                 ✓
```

**이것이 M3 에서 배운 「빈 값은 0 이 아니다」의 끝판입니다.** 한 줄 차이로 결론이 뒤집힙니다.
3일차에 만든 이동평균에서도 같은 규칙을 썼습니다 — 빈 날은 건너뛰고, 0 으로 채우지 않았습니다.

### 6단계 · 상한 — 넘은 만큼을 «남에게 주지 않는 것»

한 대상이 비중 상한을 넘으면 **넘은 만큼은 남겨 둡니다.** 다른 곳에 나눠 주면
상한이 없던 것과 같아집니다. 그리고 비교하기 **전에** 거래 비용을 먼저 뺍니다.

### 7단계 · 검증 — 한 번의 시험은 아직 증거가 아닙니다

게이트가 막는 것은 나쁜 전략이 아니라 **여러 번 시도하다 우연히 좋아 보이게 된 결과**입니다.

1. 시간 순서대로 구간을 나눈다
2. 예측 기간만큼 잘라낸다
3. **후보를 평가 «전»에 선언한다**
4. 겹치지 않는 구간으로 잰다
5. 과최적화 확률을 잰다
6. 시도 횟수를 반영해 성과를 깎는다
7. **그리고 마지막 문은 사람이 엽니다**

> 검증의 결론은 「좋다/나쁘다」가 아니라 **「이 숫자로 어디까지 말할 수 있나」**입니다.

### 8단계 · 루프 — 자동으로 도는 축과, 사람 앞에서 멈추는 축

- **자동**: 수집 · 갱신 · 점검 · 재산정 — 여기까지는 기계가 돕니다.
- **사람**: 사례를 쌓고 → 얼마나 어긋났는지 재고 → **조정안을 파일로만 만들고** →
  사람이 승인한 값만 다음 판단에 반영됩니다.

> 자동화의 범위를 「수집·계산」까지로 두고 **「규칙 변경」을 사람에게 남긴 것**이 이 설계의 결정입니다.

## 4. 이렇게 시키세요 — 그대로 붙여넣을 문장

**① 내 주제로 옮기기**

```
위 가이드의 1~8단계를 내 주제에 맞춰 다시 써줘.
내 주제는 <여기에 한 줄>이야.
각 단계마다 «내가 정해야 할 것»을 질문 형태로 뽑아 주고,
아직 정할 수 없는 칸은 지어내지 말고 「미정」이라고 남겨 줘.
```

**② 결측 규칙부터 만들기 — 여기서 시작하시길 권합니다**

```
위 가이드 3단계(결측)만 보고, 내 자료에 맞는 결측 표기 규칙표를 만들어줘.
관측값 / 미보유 / 대리값 세 칸이고, 각 칸에 «화면에 뭐라고 보일지»까지 적어 줘.
0 으로 채우는 선택지는 넣지 마.
```

**③ 검증 게이트를 내 수준으로 줄이기**

```
위 가이드 7단계는 내 규모에 너무 큽니다.
혼자서 주말에 할 수 있는 수준으로 3단계까지만 줄여 주고,
줄이면서 «포기한 것»이 무엇인지 각각 한 줄로 적어 줘.
```
